# 阶段 4：白名单内自动合入

先读 [00-入口与统一判定](00-入口与统一判定.md)、[03-阶段3-接收信号](03-阶段3-接收信号.md)、[06-Dune与CI上线门禁](06-Dune与CI上线门禁.md)。本级是受硬约束的特定合入白名单，不是整个Bot获得无人审阅的通用权限。付款、私有资料外发、任意删除、生产发布均不能从本级自动推导。

本页的30天/30候选/3类回滚/10分钟为本次制定的门槛，尚非已完成的演练或已批准自动合入范围。

## 必须同时满足的条件

| ID | 条件 | 必备证据 |
|---|---|---|
| S4-01 | 同能力阶段3已生效，A/B/C持续有效、D正式运行 | 当前版本资格、生效读回、来源真实记录与无未决回归 |
| S4-02 | 架构隔离与最小权限真正强制 | Bot不能改控制面/必需CI/保留题库/期望值/分支保护；不能读生产秘密；越权探针必须失败 |
| S4-03 | 30天连续真实CI与影子合入观察，≥30个不同真实候选变更 | 每天运行证据；每个候选有不可变head SHA、完整必需检查与独立审阅；无错误放行、无未决失败 |
| S4-04 | 已知失败模式被硬检查覆盖，验收者Eval有效 | 架构/Lint/CI反例覆盖表、旧样本变红和修复变绿、有效变异≥20且杀死率≥95%；不以多跑LLM审查替代 |
| S4-05 | 闭环E：3类回滚/止损演练全部通过 | 错误候选阻断；已合入变更原子revert；撤销授权/急停后停止执行。每次≤10分钟，附实际前后读回、命令、退出码、SHA与其他Bot未受影响证据 |
| S4-06 | 合入白名单可机检且不能由Bot放宽 | 固定仓库/目标分支/路径/变更类型/体积上限/禁止项/有效期/批准记录/允许执行器；缺字段或不匹配即转人审 |
| S4-07 | 每次实际合入均绑定同一版本的独立证据 | 当前head SHA=验证产物SHA对应版本；检查success且未取消/跳过；批准未过期；竞态时重新验证，禁止force push |
| S4-08 | 人工明确批准阶段4和白名单，平台已读回 | 阶段4不自动进入；策略批准与平台能力都在范围内；超出白名单的R3仍逐笔批准 |

30个候选可以在影子模式中被独立审阅、逐笔人批后合入，或保留为候选不合入。未实际合入的只能记“候选验证”，不能报“30次自动合入成功”。观察期不从任意全绿的最后一天倒推，期间失败必须进入账本与重新验证窗口。

## 训练与演练次序

1. 从一个最小、可逆、与敏感模块隔离的变更类型开始，先由人审每个候选，自动合入保持关闭。
2. 在隔离环境注入已知反例：伪造回执、改CI、改期望值、空检查、取消检查、摘要伪装原始输出、旧SHA批准、删除历史快照。必须被硬门禁拒绝。
3. 运行30天/30候选窗口；质量判据、分母、反例及豁免不允许被被测Bot修改。普通实现失败可训练修复，但不能把失败日隐去或改绿。
4. 做3类真实回滚/急停演练，记录从触发到目标状态恢复的时间；计时起止来自可信执行器，不用Bot自己声称“10秒完成”。
5. 独立审阅白名单规则和执行器；在白名单内、外各放一条候选，验证只允许前者，且凭据不进入不受信的代码执行环境。
6. 人工批准阶段4与确切白名单→应用→平台及执行器读回→再核其他Bot未变→才打开该白名单的自动合入。

## 自动合入的联合条件

```text
可自动合入 = 阶段4授权有效
  AND 当前候选完全匹配不可由Bot放宽的白名单
  AND 当前head SHA对应的全部必需CI与独立验收通过
  AND A/B/C/D/E有效且无冻结、回归、待复核或证据缺口
  AND 执行器权限、回滚与急停可用
```

任一条件缺失即停止自动合入并转人审。CI exit=0不代表所有闭环closed；不存在必需检查、空检查集合、skipped/neutral/cancelled都不能当成功。

## 维持与退回

每个合入保留事件→来源→任务→生产/验收消息→产物清单→commit→CI run→授权→实际合入→回滚指针的证据链。次日早报从只追加决策记录汇总，不从聊天记忆汇总。

白名单失效、急停失灵、必需检查缺失或任何错误合入，立即关闭自动合入并冻结复核；至少退回阶段3的“提交候选、人审合入”方式。若涉及边界违规则按G1退回1；编造按G2。自动合入恢复必须再获明确批准，不能修完一次就自行重开。

改变白名单、保护规则或执行权限是新的配置/授权变更；本目录的审查PASS不代替这次批准。
