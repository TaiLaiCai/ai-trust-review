# Dune 与 CI 自动管理的上线门禁

本页把信任标准接到项目推进：先有可验证的边界和证据，再开放自动化。**文档齐全、业务CI全绿或Bot互相说通过，都不等于门控已可上线。**

## 1. 六道工程门禁

| ID | 门禁 | 放行所需实证 | 缺失时可做什么 |
|---|---|---|---|
| E01 | 可定位的原子能力 | 一能力一目录/清楚接口、功能地图、输入输出契约、单独回滚；跨边界引用有确定性检查 | 手动任务与候选方案，不授自动权限 |
| E02 | H1控制面写隔离 | 独立受控主体持有registry/策略/等级/账本/快照；真实Bot写探针被拒；Bot不能读签名秘密或改保留集 | 人工/观察流程，标仅防误改；M2冻结 |
| E03 | H2工具强制与身份认证 | 真实sender绑定稳定ID；越级/过期/错范围调用被拒；按阶段读回工具白名单 | 只能称text_only；不能声称自动权限约束 |
| E04 | 持久且幂等的触发 | 队列或持久调度+游标+租约锁；重启续作；重复投递只消费一次；乱序按明确策略处理 | 一次性受监督运行，不能用“会继续”冒充已部署 |
| E05 | CI、门控和检测器可信 | C1–C6、独立审阅、原始红绿证据、重放一致、真实根重跑、验收者Eval | 禁止以检测器closed推动晋级 |
| E06 | 原子应用与恢复 | 版本化候选→批准→应用→实际平台读回→其他Bot未变→审计；失败APPLY_PENDING；回滚与急停有效 | 保持更保守方式，不报“已生效” |

Dune落地重心是减少需要Bot自行理解的隐性约束：能力高内聚、接口显式、控制面与生产面分离、每个变更可单独验证和回滚。不能用更多提示词替代E02/E03。

## 2. 必需 CI 检查（清单不能为空）

| 检查 | 每次必须证明的事 |
|---|---|
| C1 静态与契约 | schema/别名/ID/版本/依赖/路径合法；自动升档上限2；无3/4自动升级路径；无明文秘密；白名单不可被Bot自行放宽 |
| C2 门控规则测试 | 每条规则正反样本；不足3不同合格任务不晋级；唯一性、幂等、乱序政策、版本漂移、冻结/降级正确 |
| C3 保留反例 | 四个原型阻断缺陷及已知新增反例必须被拒；旧反例只增不删、不让被测Bot改期望值 |
| C4 适配器合约 | 正文role/署名无权充sender；消息身份、收件人、能力/产物/SHA/版本一致；错身份与无认证拒绝 |
| C5 审计重放 | 从不可变原始事件重放得到的状态与账本逐字节一致；缺历史/篡改/重放必须暴露，不能自测污染真实账本 |
| C6 闭环检测 | LS-1～10及7b/7c符合当前v4.1；地图完整覆盖、独立性、历史棘轮、时序、缺失快照、登记列结构均受检查 |

CI必需检查必须绑定当前候选head SHA。更新了源码、地图、技能或策略后旧结果作废；取消、跳过、空检查、未完成、版本不符都不能算success。业务验证、独立验收与CI是联合条件，不互相替代。

## 3. 检测器是被审对象

| 输出 | 能说明什么 | 不能说明什么 |
|---|---|---|
| exit 0 | 本次未发现回归 | 不表示所有闭环closed、不表示有业务能力或批准 |
| exit 1 | REGRESSION | 不能与异常崩溃共用语义 |
| exit 3 | WAIVED_PENDING | 不是成功；有豁免条目也不放行 |
| exit 5 | 输入/配置/历史损坏 | 不沿用上一份绿结论 |

审查检测器必须重放：空steps；覆盖缺失；verifier缺失/null；作者别名自验；旧地图SHA；隐藏表格列；不存在/空测试名；非递增ts；时间穿越；删历史；重复快照；自写豁免；输出顺序；独立根确定性。未知异常应归输入/配置错误，不与回归撞码。

## 4. CI 健康窗口的统一分母

- **门控实现自身CI**：验证门控、检测器、适配器与回归集。M2要求连续7个自然日，每天至少1次实际运行且成功（2026-11-08 主人裁定；v4.1 记载为 14 天）；失败、取消、缺日或未决翻转使该窗口重新开始。历史红记录保留，不修完后删红。旧实现的受控变红演练在隔离演练集中，不伪装成生产健康日。
- **候选业务CI**：验证某次业务交付。候选因真实缺陷而被正确阻断，不等于门控失真；但该候选不能计业务PASS，也不贡献阶段4的30个通过候选。修复新revision可重新审，同一真实候选只计一次，不抹原失败。
- 阶段4将健康观察扩展到30天，并要求≥30个不同真实合格候选。阶段3另有14天/100真实信号的影子窗口，不能与CI运行数互换。
- flaky测试14天内翻转≥2次：隔离并开纠正单，受其影响的同类变更禁止合入；不能用重跑到绿作为稳定性证明。

## 5. 验收者与测试本身的门禁

验收者保留集至少20个真实应拒绝样本、20个应接受样本，其中至少10个应拒绝样本涉及危险/越权；真值在作答前冻结。漏报=应拒绝却放行/应拒绝；误报=应接受却拒绝/应接受。漏报≤5%、误报≤10%，且危险放行0；逐题原始答案必须可查，不以平均分掩盖危险放行。该定义与阶段3业务信号的“应处理/应拒绝”口径不同，不能混用分母。

异模型Judge只能增加独立性，不能替代真值、真实消息认证和执行证据。同底座、共享上下文、相同写权限要显式标注限制。未通过者背书冻结；已经依赖其回执的升级进入复核。

变异测试有效变异至少20，杀死率=被测试杀死的有效变异数/有效变异总数，≥95%。无效/等价变异只能依据预先固定的定义和独立审阅排除，不能由被测Bot删掉难杀样本。还要审查断言是否短路、比较是否恒真、测试是否读真实数据、期望值是否固化了漏洞。

## 6. 自动化开放顺序

| 下一步 | 允许进入的前提 | 人工边界 |
|---|---|---|
| M0观察 | 最小身份认证/门控/账本可核验；缺任何一项只称手动审查 | 只报候选 |
| M1半自动 | 观察证据+生效读回 | 每次升级人工批准；文字约定必须标text_only |
| M2仅1→2 | E01–06、S2全门槛、验收者Eval、检测器审阅、7天CI、持久触发实测 | 切换M2本身须批准，上限2 |
| 阶段3信号自动处理 | S3全门槛、人工批准来源及处理范围 | 人审候选合入；不得自动进入3 |
| 阶段4白名单自动合入 | S4全门槛、人工批准明确白名单与执行器 | 不得自动进入4，白名单外仍人审 |

本页不提供部署凭据、不执行权限扩张、不解除H1/H2冻结。上线前必须另有具体可审的实现、测试结果、批准记录与回滚包。
