# D1 回填 · v1

Apo Labs 框架 §6 岗位契约 D1 回填的能力目录。目标：让每次决策可被事后检验，系统因此越用越准。

## 目标

让每次决策可被事后检验，系统因此越用越准。回填的 outcome 反馈给 B2 研判，用于校准后续判断。

## 验收

- 每个发行在 D7 / D30 有 outcome，含“爆”判定、非付费占比、与预期的差距、延迟分段。
- “爆”按框架 §4.1 判定并带阈值版本。
- 失败（追了没爆）必须回填，不得删除或隐藏。

## 读→写

- 读：自有后台 observation、发行事件、experiment、基线、口径与阈值版本。
- 写：outcome 事实（只追加）。

## 方式

纯确定性。不用 LLM 做判定；只做规则计算与记录。

## 规则

- “爆”按 §4.1 判定并带阈值版本；阈值变更不回改旧 outcome。
- 非付费占比 = 扣除付费归因（后台来源拆分 + 账本投放记录）；二者皆无则标低置信。
- 嵌入增量 = 观测 − 基线预测，附对照；无对照标“不可推断因果”。
- 失败（追了没爆）必须回填，不得删除或隐藏；不得事后改写假设与判断标准。
- 记录全链路延迟分段：发现、判断、创作、审批、审核、上线。
- 每季度用结算回算“爆”与“收回成本”的相关性并上报。

## 停止

- 口径或阈值未定义 → CLARIFY，停下问，严禁猜。
- 发行事件或基线缺失，导致无法判定 → 停止并上报。
- 触发授权、花钱、发布、外发，或发现无关的大范围改动 → ESCALATE，挂起交总工程师。

## 不做

- 不解释原因（交人复盘）。
- 不改写假设与判断标准，不删除或隐藏失败回填。
