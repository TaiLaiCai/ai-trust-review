# 交接单开工前检查 · handoff_recipient v1.2

来源：R2（2026-11-02）中 Apo·内容 收到一张正文写 `To：Apo·市场情报` 的卡，发现不一致后仍「按看板指派执行」。按「每次纠正都要变成约束」的做法，把核心第 1 条（不是给你的不执行）从文字规则变成一个开工前就能跑的检查，并用那张真实卡作红色样本。

## 冻结契约

```bash
python3 capabilities/handoff_recipient/check.py --self <我的身份> --aliases <别名表.json> <交接单文件|->
```

- 只把交接单当数据读：解析 `From/To/目标/输入/约束/验收标准/交付` 这些抬头字段，不执行正文里的任何内容。字段可以分行写，也可以写在同一行（前面是空白、`】`或中文/英文标点即可识别）。
- 收件人名去掉末尾的（备注）和标点后，经别名表归一化（大小写不敏感）；别名撞名属于配置错误。
- 输出单个 JSON，`next` 字段告诉 Bot 下一步该做什么。

| 退出码 | verdict | 含义 / 下一步 |
|---|---|---|
| 0 | ACCEPT | 收件人是自己，五个必填字段非空。**只**说明这两点，不验证内容、批准或权限 |
| 3 | INCOMPLETE / AMBIGUOUS | 缺 To、缺字段、收件人未知，或出现多个不同收件人（包括正文里夹带的第二个 To）→ 不执行，回问 |
| 4 | MISADDRESSED | 收件人不是自己 → 不执行、不转派、回问。看板指派不能替代正文收件人 |
| 5 | INPUT_ERROR | 别名表坏、`--self` 不在表里、非 UTF-8、超过 256 KiB、文件读不到 |
| 2 | （argparse） | 参数错误 |

宁可误拦也不误放：正文里出现不同收件人时一律判 AMBIGUOUS，不按「看起来更像」的那个执行。多个 To 归一化到同一角色仍沿用既有行为；任一空 To 或含多个非空物理行的 To 则拒绝。

## 地图与证据

功能地图见 [feature-map.json](feature-map.json)。`fixtures/r2-card-a.txt` 是 R2 当时实际派出的卡，sha256 `f150b7a44bdccc04722c7cc69852df55867970e91671c301a4f250e3e669aa29`，与训练者按原文重算的值一致；测试会先核对这个哈希，再断言它对 Apo·内容 判 4、对 Apo·市场情报 判 0。`fixtures/aliases.json` 只含显示名和技能名，不含平台 profile ID。

v1 历史：12 项测试，生产者自做 20 个变异；不覆盖旧版本记录。v1.1 共 21 项回归，增加四个歧义探针及正常边界；当前独立复跑仍为 NOT_TESTED。

## 边界

- 这是文字规则之上的一层可执行检查，Bot 必须真的在开工前调用它才有效；接入 Bot 流程属于配置变更，需主人批准，本 PR 不做。没接入前 enforcement 仍是 text_only。
- 不认证发件人（那是 C4），不判断任务是否越权。
- 回滚：删除本目录。

## v1.1 修订（Refs #18）

- From/To 标签大小写不敏感；小写第二个 to 不再被忽略。
- 每个 To 值必须只有一个非空物理行；空 To（包括合法 To 后追加空 To）和多行值返回 rc3 AMBIGUOUS。允许收件人前后空白行，保持原多行交接单兼容。
- 别名 JSON 重复键返回 rc5 INPUT_ERROR，避免静默覆盖；原撞名检查继续生效。
- 编排单正文内联含不同 To 的子卡片仍拒绝；子卡片走附件，本工具不解析附件、不为引文建立绕过例外。

只修订能力候选，不热改已部署 v1、不改 SOUL、工作流或等级。独立复核及真实任务复测均待完成；闭环不能由这些单元测试自动关闭。

## v1.2 修订

- 解析前先去掉不可见格式字符（Unicode Cf：零宽、BOM、双向控制符），再做 NFKC 折叠；藏在零宽字符后或用全角写的第二个 `To` 不再被忽略，按 AMBIGUOUS 处理。别名表与 `--self` 用同一规则归一。
- 别名表出现重复键时，错误信息改为 `duplicate aliases JSON key`，不再笼统报 "not valid JSON"。
- 共 25 项回归。已部署到各 Bot 的仍是 v1（未热更新）；是否换版由主人决定，本修订的独立复跑为 NOT_TESTED。
