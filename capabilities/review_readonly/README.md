# 审查只读交付检查 · review_readonly/v1

Refs #37，C-R5-2 的最小可执行约束。审查前后比较**显式列出的原件**，或 `--tree` 列出的目录下全部普通文件的字节数与 SHA256。变化、丢失或目录内新增时阻断使用本检查的交付命令。虚构夹具，不包含真实训练题或判据。

## 契约与调用

1. **受控训练者**选择根目录和被审范围，在审查开始前运行 snapshot；把原始 JSON 保存到工作 Bot 不可写的控制目录，同时独立保存其原字节 SHA256。范围用 `--file`（显式文件，可重复）或 `--tree`（目录清单，可重复，`.` 表示根目录本身），至少给一个。
2. 被审 Bot 完成审查，只输出新的 review 文件，不能改原件。输出 review 文件须放到被审集之外；不能把 baseline 输出重定向到任何被审原件。
3. **受控训练者**在交付前执行 verify，提供开工前冻结的 baseline SHA256。进程退出码就是交付门：仅退出 0 且 JSON `delivery_allowed=true` 才可交付。退出 1（内容不同、缺失、改名，或 `--tree` 范围内新增）和退出 5（基线/路径/符号链接/特殊文件/超限）都是非 0，调用方必须停下。不得重建基线、就地改原件、或恢复成原样后重试来消掉失败。

```bash
python3 capabilities/review_readonly/check.py snapshot \
  --root /trusted/review-input --tree .
# 或只锁定显式文件：--file document.txt --file nested/data.json
# 将 stdout 的原始字节存为 before.json，并把它的 SHA256 独立冻在受控处。
python3 capabilities/review_readonly/check.py verify \
  --root /trusted/review-input --baseline /trusted/control/before.json \
  --baseline-sha256 '<开工前冻结的64位摘要>'
```

`/trusted/...` 是示意路径，本工具不创建或管理这些隔离目录。只使用标准库。目录清单直接对目录描述符枚举（`os.listdir(fd)`），不经过 `/proc/self/fd` 或 `/dev/fd` 路径；该调用不可用的平台按退出 5 直接拒绝。

`&&` 只是 shell 使用退出码的一种写法（`verify && delivery`），不是另一套检查。不调用本工具，或把非 0 吃掉再交付，本工具无法拦住；那是控制面（H1/H2）的事。本工具不提供「代跑交付命令」的入口，避免把交付执行权放进检查器。

snapshot 输出固定 `schema_version`、绝对 `root`、`files`（规范 POSIX 相对路径→bytes/sha256）。使用了 `--tree` 时多一个已排序的 `trees` 数组。`--file` 的输出不含 `trees`，旧基线仍可 verify。verify 核对基线原字节摘要、严格格式和同一 root。`--file` 只读基线登记的文件，未登记的新文件不在范围内。`--tree` 会重走这些目录：多出的路径记入 `changed.added`，缺失记入 `changed.removed`，字节或摘要变化记入 `changed.modified`，任一非空则退出 1。符号链接、FIFO、设备文件、套接字在清单里仍是退出 5。输出排序、UTF-8、LF；不执行任何文件或卡片正文，不联网、不修改原件或基线。

| 退出码 | 含义 | 允许交付 |
|---|---|---|
| 0 | snapshot 成功，或 verify 为 UNCHANGED | 仅 verify 的 delivery_allowed=true 允许 |
| 1 | verify 发现内容不同、文件/中间目录缺失、原件改名，或 tree 范围内新增 | 否 |
| 5 | 基线篡改/坏摘要/坏 JSON/路径、基线落在审查根内或与被审文件同 inode、符号链接、特殊或不可读文件、超限、读取过程中文件被改 | 否 |
| 2 | CLI 使用错误（例如 snapshot 没有 `--file` 也没有 `--tree`） | 否 |

每次 snapshot 的显式文件加目录内文件合计 1 至 1024 个（空目录的 `--tree` 允许 0 个文件，以便之后新增能被看见）。拒绝重复路径、绝对/点/父路径、空段、反斜线、冒号和 NUL。摘要 64 位小写 hex，字节数严格非负整数，拒绝未知字段/JSON 重复键。单文件 64MiB、合计 256MiB、基线 1MiB。空普通文件合法。CRLF 与 LF 是不同字节，改写后退出 1，不会被折成同一行。

根目录最后一段、中间目录和文件均用 O_NOFOLLOW + 目录描述符打开；只读普通文件，FIFO 用 NONBLOCK 打开后拒绝，避免挂住。根的祖先目录由调用方信任；路径本身不是授权来源。读取时检测文件大小/时间戳变化；输入须保持静止。

## 信任假设

防伪不来自本工具私藏的密钥。它只做两件事：核对调用方传入的 `--baseline-sha256` 与基线文件原字节是否一致，再把基线里的路径与当前字节比较。

- 基线原字节和 SHA256 必须由受控训练者在 snapshot 成功的当时冻结，放在 Bot 不可写的位置。verify 时不得改为「把当前基线文件再哈希一遍」。Bot 若能同时改基线和这份冻结摘要，就可以伪造一份自洽的前后记录；这要靠 H1，不靠本工具。
- 廉价硬化：基线路径落在 `--root` 之内，或基线 inode 与任一被读到的被审文件相同（硬链接进被审树），直接退出 5。这挡的是「基线和原件放在同一棵可写树里」的常见失误，不是可信根。
- 硬链接到树外、祖先目录被掉包、检查之后再写、改完又改回相同字节，仍不在本工具能证明的范围内。

## 实际边界

- 这是前后两次字节观察。修改后恢复相同字节、只改元数据、`--file` 未列出的文件，以及检查之后再写，均不由本工具证明不存在。`--tree` 把「目录里新增普通文件」纳入同一次观察，但空目录被删掉而没有文件字节变化时仍然看不见。测试明确保留「改后恢复仍 UNCHANGED」，不能伪称全程无写入。
- 不提供 OS 只读挂载、H1/H2、身份认证、锁或交付平台钩子。
- snapshot 失败可能使 shell 重定向留下错误 JSON；受控方必须核对 snapshot 退出码，不能把错误输出登记成基线。
- 「就地修正前先回问」是审查者的训练规则（B08），不是本工具的职责。本工具不解析卡片里的自然语言，也不实现回问对话；卡里只读与修复冲突时，审查者自己停下回问。
- 本修订不部署到 Bot、不改 SOUL/权限/等级、不关闭纠正单。真实 Bot 接入与独立验收、换包装复测仍 NOT_TESTED；CI 通过不计业务连胜。设备节点没有在本环境造出来，该项 NOT_TESTED；FIFO 与符号链接有回归。
