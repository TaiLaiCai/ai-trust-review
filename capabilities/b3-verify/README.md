# B3 核验 · v1

Apo Labs 框架 §6 岗位契约“B3 核验”的原子能力目录：独立回答“自然趋势，还是被推出来的”，并复核 B2 的阶段与窗口。

## 目标

独立回答“自然趋势，还是被推出来的”，并复核 B2 的阶段与窗口。

## 验收

- 产出 verdict（交叉确认｜单源待证｜疑似人为）+ 证据清单 + 缺哪层信号。
- 每条 verdict 可追溯到证据与当前 revision；revision 任一变动，旧验证作废并重跑。
- 证据不足时不放行（fail-closed）。

## 读→写

- 读：hotspot、多层信号（S 层与 A 层观测）、投放 / 活动日历。
- 写：verdict 事实（仅追加）、证据清单。
- 不写账本、不写作品库、不改 B2 的 hotspot。

## 方式

确定性规则出初判，LLM 仅汇总证据。

## 规则

- 交叉确认需 ≥2 层信号（S 出现且 A 开始跟随）。
- 单平台单层 → 单源待证。
- 疑似人为线索逐条列证据（形态陡直、无自然扩散、与投放日重合、互动结构异常）。
- 证据不足不放行（fail-closed）。

## 独立性要求

**B3 与 B2 不得同一实例。** B3 必须由与产出该 hotspot 的 B2 不同的实例执行；同一实例既研判又核验，核验无效。若发现 B3 与 B2 为同一实例，立即停止并上报总工程师。

## 停止

- 证据不足 → 不放行，写“单源待证”并列出缺哪层信号。
- 口径未定义 → CLARIFY，停下问，严禁猜。
- 需要新增来源、授权、花钱、发布、外发 → ESCALATE，挂起交总工程师。
- 发现 B3 与 B2 为同一实例 → 停止并上报。

## 不做

- 不断言“造假”。
- 不决定追不追。
- 不指挥其他 bot，不验收自己的产出。
