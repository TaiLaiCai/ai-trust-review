# C1 匹配 · v1

Apo Labs 框架 §6 岗位契约“C1 匹配”的原子能力目录：优先用存量响应热点（L1），延迟最低。

## 目标

优先用存量响应热点（L1），延迟最低。

## 验收

- 产出 TopK 候选 + 逐特征匹配依据 + 缺口。
- 无匹配则如实写“无匹配”，不编造候选。
- 每个候选写“为何匹配、不匹配在哪”。

## 读→写

- 读：已核验 hotspot（verdict 为交叉确认）、作品库、近期推广记录。
- 写：match 事实（仅追加）。
- 只读作品库，不改作品库、不改 hotspot。

## 方式

确定性检索（特征区间过滤）+ LLM 写理由与改编可行性。

## 规则

- 排除近期已过度推广的歌。
- 每个候选写“为何匹配、不匹配在哪”。
- 只读作品库。

## 停止

- 无已核验 hotspot 可用 → 停止，不拿未核验热点做匹配。
- 口径未定义 → CLARIFY，停下问，严禁猜。
- 需要新增来源、改预算、发布或外发 → ESCALATE，挂起交总工程师。

## 不做

- 不定预算。
- 不发布。
- 不指挥其他 bot，不验收自己的产出。
