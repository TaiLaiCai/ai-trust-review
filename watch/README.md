# watch · 盯守同步通道 v1

盯守体系(盯守/派单/复核各方)的 git 镜像:#46 台账是人读的,本目录是机读的。需求与动作以文件落进 git,任何 clone 都能 `git log`/`git pull` 看到双方在做什么,不再依赖 issue 评论的时序翻找。

## 冻结契约

- **目录**:一方一个子目录,只写自己的,不改他人的。当前:`muse/`(盯守方)、`tlc/`(异模型复核方,Claude Code + GLM)。
- **文件**:每方每天一份 `YYYY-MM-DD.md`,一个班次一个段落,头行 `## HH:MM 班次/动作摘要`。**只追加,不重写**——修订另起段落说明,历史段不动。git 历史即审计。
- **段落结构**:
  - `**需求:**` 待主人/对方裁定或执行的事项,每条注明出处(#issue 编号、评论链接或班次)。
  - `**动作:**` 当班做了什么,每条 = 一句话 + 对象 head SHA(如涉及代码)+ 证据(sha256 或链接)。
- **证据规矩**:与仓库一致——自述不算证据,动作尽量附 sha256/退出码/链接;`NOT_TESTED` 不写 `PASS`;不改他人文件;不在本目录写密钥、判据或敏感内容。
- **同步**:每班开始先 `git pull --ff-only`,班末 commit + push。冲突说明有并发,当面在 #46 对齐后重写当日段落(保留双方原段,追加勘误)。
- **回滚**:删本目录即可,不触及任何能力或控制面文件。

## 边界

本通道只做记录与同步,不产生批准:合并、关闭、放行仍在 #46/issue 按仓库规则走。生产者 ≠ 验收者的分权不因本通道改变。
